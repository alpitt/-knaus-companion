# Procedures Guide

Sprint 14 adds a local Procedure Library for owner-authored, source-derived, adapted and visibly generic drafts. A template provides structure only; it never supplies technical truth.

## Create and edit

Create a draft from **Procedure Library**. Record title, purpose, category, type and exact sources. Add stable step IDs, explicit branches, hold points, tools, parts, consumables, PPE, hazards, warnings, prohibitions, assumptions, limitations and completion criteria only when known. Missing information remains visible. Reorder steps explicitly (including keyboard controls where available) and validate before review.

Owner-authored content is labelled as such. Source-derived content retains exact manufacturer-manual, Engineering Canon, Companion chapter, component and system references. Generic templates remain generic after use.

## Lifecycle and versions

Drafts move through source and review states only by explicit owner action. Activation, deprecation, withdrawal, archive and supersession require a reason. Approved versions are immutable; edits create a new unapproved version and preserve history.

## Use and sharing

Print or export only the selected procedure/version. Imports are previewed, validated and never silently overwrite a record. Backups contain procedure metadata automatically and remain local. No cloud or binary interpretation is used.

## Troubleshooting and privacy

A missing-source warning is expected for an incomplete draft, not an application failure. Resolve broken branch targets and references locally. Procedure data uses the existing local saved state and is private unless the owner exports it.
