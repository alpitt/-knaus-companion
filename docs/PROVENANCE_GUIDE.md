# Provenance guide

Provenance explains how an ownership record relates to another explicit record. It does not certify legality, accuracy, causation, compatibility or identity.

Owner-confirmed links are explicit owner assertions. Derived links must expose a deterministic rule ID. Both endpoints must exist; self-links, duplicates and invalid replacement cycles are rejected. Broken links and conflicts remain visible.

Component history keeps the reference Digital Twin read-only while displaying owner-observed, proposed, installed, removed and archived states. System history aggregates unique explicit records without rewriting the System Graph or double-counting shared events. Evidence, measurements, revisions and replacement chains retain source identifiers.

Use the Provenance Explorer’s accessible list to inspect upstream and downstream records. Reports are locally generated and are not legal provenance certificates.
