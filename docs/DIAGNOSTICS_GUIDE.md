# Diagnostics guide

A diagnostic is a versioned, source-aware investigation definition. It is not a generated diagnosis, repair recommendation, certification, or statement of roadworthiness. Start from the Diagnostic Library, choose explicit symptoms and component/system context, review readiness, then follow only configured branches. Observations remain descriptions; measurements preserve original values and units; criteria must be explicitly sourced or labelled owner-authored. Evidence is linked but never interpreted. Escalated, unresolved, insufficient-evidence, and supported-conclusion outcomes remain distinct. A supported conclusion is not a confirmed root cause. Root causes and resolutions require separate explicit records. Print and exports retain identifiers, sources, limitations, and tested scope. Backups use the existing local schema and storage key. All records remain on this device. If a draft cannot start, review missing source, node, tool, PPE, or explicit branch information rather than inventing it.
